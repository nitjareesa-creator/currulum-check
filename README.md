# README — เว็บเวอร์ชัน Static (หมวดวิชา & แผนการศึกษารายเทอม)

เอกสารนี้ครอบคลุม **เฉพาะส่วนเว็บแบบ static** ของโปรเจกต์ระบบจัดการข้อมูลหลักสูตรปริญญาตรี
ไม่ได้อธิบายส่วน Desktop (PySide6) หรือชั้นฐานข้อมูล — ดูรายละเอียดส่วนนั้นได้ใน `PROJECT_SUMMARY.md`

---

## 1. ภาพรวม

ส่วนเว็บของโปรเจกต์นี้ **ไม่ใช้เซิร์ฟเวอร์เลย** (ไม่มี `uvicorn`, ไม่มี Node.js, ไม่มี build step)
แนวคิดคือ:

1. รันสคริปต์ Python หนึ่งครั้ง → มันอ่านข้อมูลจากฐานข้อมูล SQLite ผ่าน `repository.py`
2. แล้ว "พิมพ์" ข้อมูลทั้งหมดฝังลงไปในไฟล์ HTML เดี่ยวๆ (snapshot)
3. ผู้ใช้ดับเบิลคลิกไฟล์ `.html` เปิดในเบราว์เซอร์ได้ทันที ทำงานแบบ offline 100%

เหตุผลที่เลือกแนวทางนี้: ความต้องการจริงคือ **แค่ดูข้อมูล** ไม่ต้องเชื่อมฐานข้อมูลตลอดเวลา
จึงไม่คุ้มที่จะต้องมีโปรเซสเซิร์ฟเวอร์ค้างไว้

**ข้อแลกเปลี่ยนที่ต้องเข้าใจ:** ไฟล์ HTML เป็น *สแนปช็อต* ไม่ sync อัตโนมัติ —
ถ้าข้อมูลในฐานข้อมูลเปลี่ยน ต้องรันสคริปต์ export ใหม่ทุกครั้ง

```
database.db (SQLite)
        │
        ├── repository.py ──> export_tree_view.py ─────> tree_view.html
        │                 └─> export_schedule_view.py ─> schedule.html
        │
        └──────────────────── เบราว์เซอร์ (ดับเบิลคลิก เปิดได้เลย)
```

> (ข้อมูลทุกหลักสูตร/ทุกแผนฝังอยู่ในไฟล์เดียว) จึงไม่สะดวกแนบมาในเอกสาร

> เพราะ `DATA` ยังไม่ใช่ array
>
> ต้องการตรวจไฟล์ฉบับเต็มที่อยู่ในเครื่องคุณเอง ใช้ `check_export.py` (ดู §7.1) — ไม่ต้องส่งไฟล์มาให้ใครดู

## 3. วิธีสร้างไฟล์ HTML

```bash
# 1) เตรียมฐานข้อมูล (ถ้ายังไม่มี)
python seed_data.py

# 2) สร้างไฟล์เว็บ (เลือกได้ทั้งสอง หรืออันใดอันหนึ่ง)
python export_tree_view.py        # -> tree_view.html
python export_schedule_view.py    # -> schedule_view.html

# 3) เปิดไฟล์ผลลัพธ์
#    Windows : ดับเบิลคลิกไฟล์
#    macOS   : open tree_view.html
#    Linux   : xdg-open tree_view.html
```

**รูปแบบการทำงานของสคริปต์ export** (เหมือนกันทั้งสองตัว):

- เรียก `repository.py` เพื่อดึงข้อมูลของ **ทุกหลักสูตร / ทุกแผนทางเลือก** (ไม่ต้องระบุหลักสูตรตอน export)
- แปลงเป็น JSON แล้วแทนที่สตริง `__DATA_JSON__` ในเทมเพลต
- เขียนผลลัพธ์เป็นไฟล์ `.html` เดี่ยว (ข้อมูล + CSS + JS อยู่ในไฟล์เดียว) → ส่งต่อ/แชร์ได้เลย

การเลือกหลักสูตรและแผนทำได้ **ในหน้าเว็บ** ผ่าน dropdown ไม่ต้อง export แยกไฟล์ต่อหลักสูตร

## 4. หน้า 1 — [`tree_view.html`](tree_view.html) : หมวดวิชา (Tree View)

### ใช้ทำอะไร
ดูว่าแต่ละหลักสูตรมีหมวดวิชาอะไรบ้าง แต่ละหมวดมีวิชาอะไร วิชาไหนบังคับ/วิชาเลือก และแนะนำให้เรียนปี/เทอมไหน

### ฟีเจอร์
- **Dropdown เลือกหลักสูตร** — แสดงชื่อหลักสูตร + ข้อมูลหัวหลักสูตร (คณะ | ปี พ.ศ. | หน่วยกิตรวม)
- **Dropdown เลือกแผนทางเลือก (ใหม่)** — กรองให้เหลือเฉพาะวิชาของแผนที่เลือก (เช่น `PROJECT` / `COOP` / `OVERSEA_TRAINING`)
  พร้อมชิปสรุป "วิชาบังคับตามแผน" ให้เห็นตัวเลขของทุกแผนพร้อมกันในบรรทัดเดียว
  ค่าเริ่มต้นคือ **แผนแรก** เพื่อให้ตัวเลขตรงกับที่ต้องเรียนจริง และยังมีตัวเลือก "ทุกแผน (รวมวิชาของทุกแผน)" ไว้ดูภาพรวม
- **Tree ซ้อนหลายชั้น** — หมวดใหญ่ → หมวดย่อย → รายวิชา (คลิกหัวหมวดเพื่อยุบ/ขยาย)
- **ป้ายกำกับในแต่ละหมวด** — ประเภทหมวด (`group_type`) + **หน่วยกิตที่คำนวณได้จริงของหมวดนั้น**
  (`บังคับ N นก. (M วิชา)` / `เลือก N นก. (M วิชาที่เปิด)`) + เกณฑ์ `min_credits` / `max_credits`
- **แต่ละวิชาแสดง** — รหัส, ชื่อไทย, หน่วยกิต, badge `บังคับ`/`เลือก`, ปี/เทอมที่แนะนำ
  และ badge `แผน COOP` สำหรับวิชาที่บังคับเฉพาะแผนนั้น
- **ช่องค้นหา** — กรองด้วยชื่อวิชาหรือรหัสวิชา (ค้นแบบ substring, ไม่สนตัวพิมพ์เล็ก/ใหญ่)
  เมื่อเจอวิชา ระบบจะ **auto-expand หมวดพ่อแม่ทุกชั้น** ให้เห็นผลลัพธ์ทันที
- หมวด GenEd (ที่ใช้ร่วมกันทุกหลักสูตร) ถูกจัดให้อยู่ล่างสุดเสมอ ตามที่สคริปต์ export เรียงมาให้

### ลักษณะการใช้งาน
อ่านอย่างเดียว (read-only) ทั้งหมด — ไม่มีการแก้ไขข้อมูลในหน้านี้

---

### 4.1 ตัวกรองแผนต้องมีข้อมูลอะไร (สำคัญ)

ตัวกรองแผนทำงานได้ก็ต่อเมื่อ **แต่ละรายวิชาบอกว่าตัวเองสังกัดแผนไหน** ข้อมูลจาก
`CurriculumCourse.study_plan_id` มีอยู่แล้วในฐานข้อมูล แต่ `export_tree_view.py` เดิมไม่ได้ส่งออกมาด้วย
จึงต้องเติม 2 อย่างลงใน JSON ของแต่ละหลักสูตร:

```jsonc
{
  "name": "...", "faculty": "...", "total_credits": 138,

  // 1) รายการแผนของหลักสูตร (ใช้สร้าง dropdown + แปลง id -> code)
  "plans": [ { "id": 1, "code": "PROJECT", "name": "แผนโครงงานพิเศษ" }, ... ],

  "tree": [
    { "name": "หมวดวิชาเฉพาะ", "courses": [
        // 2) รหัสแผนของแต่ละวิชา — ไม่มีคีย์นี้ = ใช้ร่วมกันทุกแผน
        { "code": "01236111", "credits": 3, "is_required": true, "plan_code": "COOP" }
    ] }
  ]
}
```

ตัวอย่างจุดที่ต้องแก้ใน `export_tree_view.py` (ตอนแปลง `CurriculumCourse` เป็น dict):

```python
"plan_code": cc.study_plan.code if cc.study_plan else None,
```

และใส่ `"plans": [{"id": p.id, "code": p.code, "name": p.name} for p in curriculum.study_plans]`
ใน dict ของหลักสูตร

**ชื่อฟิลด์ที่หน้าเว็บรับได้** (เลือกใช้อย่างใดอย่างหนึ่ง): `plan_code`, `study_plan_code`,
`study_plan_id`, `plan_id`, `plan_codes: []`, `plans: []` — ถ้าให้มาเป็น **id** หน้าเว็บจะแปลงเป็น
**code** ให้เองโดยดูจาก `plans` (จึงควรส่ง `plans` มาด้วยเสมอ)

> **ยังแก้สคริปต์ export ไม่ได้?** ใช้ `add_plans_to_tree.py` เติมข้อมูลย้อนหลังได้ —
> มันอ่านไฟล์ schedule (ซึ่งรู้ plan ของทุกแถวอยู่แล้ว) แล้วจับคู่ด้วยรหัสวิชา
> ดูคำสั่งใน §7.4

**ถ้าไม่มีข้อมูลแผนเลย** หน้า tree จะยังใช้งานได้ตามปกติ แต่ dropdown แผนจะถูกปิด
และขึ้นแบนเนอร์เตือนว่าตัวเลขที่เห็นคือ **ยอดรวมทุกแผน** (ไม่ใช่บั๊ก — เป็นการบอกข้อจำกัดของข้อมูลตรงๆ)

## 5. หน้า 2 — [`schedule.html`](schedule.html) : แผนการศึกษารายเทอม

### ใช้ทำอะไร
ดูแผนการเรียนทีละเทอมของแต่ละหลักสูตร/แผนทางเลือก พร้อม **ลองเลือกวิชาเลือกและกรอกเกรดเพื่อดู GPA เบื้องต้น**
แล้วบันทึกไว้เป็นไฟล์เพื่อกลับมาเปิดดูทีหลังได้

### ฟีเจอร์หลัก

**ก) การแสดงตาราง**
- Dropdown **หลักสูตร** → Dropdown **แผนทางเลือก** (PROJECT / COOP / OVERSEA_TRAINING หรือ "เฉพาะวิชาร่วม" ถ้าไม่มีแผน)
- แสดงเป็น card แยกตาม **ปีที่** → หัวข้อย่อยตาม **เทอม**
- แต่ละแถว: รหัสวิชา | ชื่อวิชา | หน่วยกิต | หมวดวิชา | ประเภท (บังคับ/เลือก) | **ช่องเกรด**
- กล่องสรุปด้านบน: ชื่อหลักสูตร + แผน, **หน่วยกิตตามตารางที่เลือกไว้ (คำนวณสด) เทียบกับหน่วยกิตรวมหลักสูตร**
- ท้ายแต่ละปีแสดงหน่วยกิตรวมของปีนั้น (ค่านี้เป็นค่าคงที่จากฐานข้อมูล ไม่เปลี่ยนตามที่เลือก)

**ข) แถว placeholder วิชาเลือก (`xxxxxxxx`)**
จำนวนแถวมาจากตาราง `ElectiveTermSlot` จริง (จำนวนช่องที่ต้องเลือกต่อหมวด/เทอม/แผน) มี 2 แบบ:

| แบบ | ลักษณะ | วิธีใช้ |
|---|---|---|
| **เลือกจากกลุ่ม** | `<select>` ที่มีเฉพาะวิชาในกลุ่มนั้น | เลือกแล้วรหัสวิชา + หน่วยกิตจะถูกเติมให้อัตโนมัติ |
| **เลือกเสรี (free elective)** | ช่องพิมพ์ข้อความ | พิมพ์ **รหัสวิชา** ถ้ารหัสมีอยู่ในระบบจะ auto-fill ชื่อ + หน่วยกิตให้ และขึ้นรหัสเป็นตัวหนาสีฟ้า หรือจะพิมพ์ชื่อวิชาเองก็ได้ (หน่วยกิตจะกลับไปใช้ค่าเริ่มต้น) |

**ค) กรอกเกรด + คำนวณ GPA**
- ตัวเลือกเกรด: `A, B+, B, C+, C, D+, D, F, S, U` (ค่าว่าง = ยังไม่กรอก)
- คิดเกรดตามหน่วยกิตของแถวนั้น: `A=4.0, B+=3.5, B=3.0, C+=2.5, C=2.0, D+=1.5, D=1.0, F=0.0`
- **`S` / `U` และช่องว่างถูกข้าม** จากการคิด GPA (ไม่นับเป็นหน่วยกิตที่คิดเกรด)
- แสดงผลบนหัวหน้าเว็บ: `GPA: x.xx (หน่วยกิตที่คิดเกรด n)`

**ง) บันทึก / เปิดไฟล์ (ทำงานฝั่ง client ล้วน)**
- **บันทึกเป็นไฟล์** → ดาวน์โหลด `.json`
  - Chrome/Edge: เปิด dialog ให้เลือกตำแหน่งและตั้งชื่อไฟล์เอง (File System Access API)
  - Firefox/Safari: ดาวน์โหลดลงโฟลเดอร์ Downloads ตามชื่อที่ระบบตั้งให้
  - ชื่อไฟล์อัตโนมัติ: `<ชื่อหลักสูตร>_<วันที่-เวลา>.json` (ตัดอักขระต้องห้ามของ Windows ออก)
  - ถ้าไม่มีข้อมูลให้บันทึกเลย (ไม่มีรหัสวิชา/เกรด) จะแจ้งเตือนและไม่สร้างไฟล์
- **เปิดไฟล์ที่บันทึกไว้** → เลือกไฟล์ผ่าน dialog **หรือลากไฟล์มาวางบนหน้าเว็บก็ได้**
  - ตรวจว่าเป็น JSON ที่ถูกต้อง และมี `rows` เป็น array
  - ถ้าชื่อหลักสูตรในไฟล์ไม่ตรงกับหน้าปัจจุบัน → `confirm()` ถามก่อนโหลด
  - ถ้า `rowCount` ไม่ตรงกับจำนวนแถวปัจจุบัน → เตือนว่า *ข้อมูลอาจเลื่อนไม่ตรงแถว* แล้วให้เลือกว่าจะโหลดต่อไหม
- **ล้างตาราง** → คืน dropdown วิชาเลือกและช่องเกรดทั้งหมดเป็นค่าว่าง แล้วคำนวณ GPA ใหม่
  (หมายเหตุ: โค้ดส่วนล้างยังไม่ได้เคลียร์ช่องกรอกวิชาเลือกเสรี — ดู §8)

### รูปแบบไฟล์ที่บันทึก (`.json`)

```json
{
  "app": "study-plan",
  "version": 1,
  "curriculum": "ชื่อหลักสูตร (ใช้เตือนตอน import)",
  "savedAt": "2026-10-31T08:37:00.000Z",
  "rowCount": 148,
  "rows": [
    { "code": "01236111", "name": "", "credits": "3", "grade": "A" },
    { "code": "",         "name": "", "credits": "3", "grade": ""  }
  ]
}
```

- `rows` เรียงตาม **ลำดับแถวบนหน้าจอ** (วิชาบังคับของเทอมนั้นๆ ก่อน แล้วตามด้วยช่องวิชาเลือก)
- `credits` เป็น **string** (มาจาก `data-credits`)
- ตอน import จะจับคู่ด้วย **index ของแถว** ไม่ใช่รหัสวิชา
  → ถ้าเปลี่ยนหลักสูตร/แผนก่อน import ต้องยอมรับว่าแถวอาจไม่ตรงกัน (มี `confirm()` เตือนไว้แล้ว)

### สิ่งสำคัญที่ต้องเข้าใจ
การเลือกวิชา/กรอกวิชาเอง/ใส่เกรดในหน้านี้ **เป็นเพียงการดูตัวอย่างในเบราว์เซอร์เท่านั้น**
ไม่มีการเขียนกลับลงฐานข้อมูล ไม่มีการส่งข้อมูลออกไปที่ใด (ยกเว้นตอนกด "บันทึกเป็นไฟล์" ซึ่งเป็นไฟล์ในเครื่องคุณเอง)
ปิดหน้าเว็บเมื่อไร ค่าที่กรอกไว้จะหายไป — ต้องกดบันทึกเป็นไฟล์ก่อนถ้าอยากเก็บไว้

### 7.1 ตรวจไฟล์ที่ export มาโดยไม่ต้องเปิดเบราว์เซอร์

ถ้าต้องการยืนยันว่าไฟล์ในเครื่องตัวเองสมบูรณ์ (เช่น ก่อนส่งให้อาจารย์ หรือหลังแก้สคริปต์ export)



→ **ยืนยันได้ด้วยตัวเลขว่า "หน่วยกิตรวมตรงเป๊ะทุกแผนทางเลือก" ตามที่ระบุใน `PROJECT_SUMMARY.md` §1 เป็นความจริง**
(ตัวเลขในตารางนี้คือหน่วยกิต ไม่ใช่จำนวนแถว — วิชาบังคับบางวิชาเป็น 1–2 นก. จึงมีแถวมากกว่าหน่วยกิต)

#### จำนวนแถวและช่องวิชาเลือก (หน้า schedule)

| หลักสูตร | PROJECT | COOP | OVERSEA | เฉพาะวิชาร่วม (ไม่ใช่แผนจริง) |

| ไอโอทีและสารสนเทศ (2569) | 48 + 10 | 47 + 10 | 47 + 10 | 46 + 6 → 120 นก. |
| สองปริญญา | 63 + 10 | 62 + 10 | 62 + 10 | 61 + 5 → 154 นก. |
| ComIoT | — | — | — | 37 + 9 → 118 นก. ✓ |
| ฟิสิกส์อุตสาหกรรม | 43 + 9 | 42 + 9 | 42 + 9 | 41 + 9 → 116 นก. |
| IoT (2565) | 40 + 12 | 39 + 12 | 39 + 12 | 38 + 7 → 114 นก. |

> รูปแบบ "A + B" = จำนวนแถววิชาบังคับ + จำนวนช่องวิชาเลือก

#### ข้อสังเกตที่ได้จากผลตรวจ

1. **COOP กับ OVERSEA มีจำนวนแถวเท่ากันทุกหลักสูตร และต่างจาก PROJECT เพียง 1 แถว** → วิชาที่ต่างกันจริงระหว่างแผนมีแค่ 1 ตัวต่อแผน และหน่วยกิตบังคับของทั้งสามแผนเท่ากัน (เช่น IoT 108 นก. ทุกแผน) การออกแบบ `study_plan_id` ทำงานถูกต้องตามที่ตั้งใจ
2. **ตัวเลือก "เฉพาะวิชาที่ใช้ร่วมกันทุกแผน" ไม่ใช่แผนที่เรียนจบได้** — ขาด 6–21 นก. เพราะแสดงเฉพาะวิชาที่ `study_plan_id = NULL` ถ้านักศึกษาเลือกตัวนี้แล้วเข้าใจว่าเรียนแค่ 120 นก. ก็จบ จะเข้าใจผิด (ดู §8 ข้อ 4)
3. **ยกเว้น ComIoT** ที่ตัวเลือกนี้ = แผนเต็มพอดี (118 ✓) เพราะหลักสูตรนั้นไม่มีวิชาเฉพาะแผนเลย → การแก้ต้องแยกสองกรณี ไม่ใช่ซ่อนทั้งหมด
4. **ตัวเลขวิชาในหน้า tree ไม่มีรหัสซ้ำ** (379 แถว = 379 รหัส) — เด็กดี ไม่มีวิชาถูกผูกซ้ำหลายหมวด
5. **แต่หน่วยกิตบังคับในหน้า tree สูงกว่าที่ต้องเรียนจริงในแผนเดียว 12 นก. ทุกหลักสูตรที่มีแผน** — อธิบายใน §7.3
6. ลำดับหลักสูตรในสองไฟล์ **ตรงกัน** (เรียงตาม `display_order`) ✓

### 7.3 ทำไมตัวเลขในหน้า tree กับ schedule ไม่เท่ากัน (ไม่ใช่บั๊ก)

| หลักสูตร | หน่วยกิตบังคับในหน้า **tree** | หน่วยกิตบังคับในแผน **PROJECT** | ต่าง |

**สาเหตุ:** หน้า tree แสดง *ทุกหมวดของหลักสูตร* โดยไม่กรองตามแผน → วิชาที่บังคับเฉพาะแผนจะถูกนับรวมกันหมด

ซึ่งเป็นคนละวิชาแต่เป็น "วิชาบังคับ" ทั้งคู่ในแผนของตัวเอง — นักศึกษาเรียนจริงเพียงวิชาเดียวตามแผนที่เลือก

> ของแต่ละวิชา (ดู §4.1) และใช้ `check_export.py` เทียบกับไฟล์ schedule ได้โดยตรง

### 7.4 ทดสอบเทมเพลตด้วยข้อมูลหลักสูตรเดียว (ไม่ต้อง export เต็ม)

`schedule_view.html` / `tree_view.html` เป็นเทมเพลตที่ยังมี `__DATA_JSON__` อยู่ ถ้าอยากเห็นหน้าตาจริงก่อน
export ทั้ง 5 หลักสูตร ให้ใช้ `build_preview.py` เติมข้อมูลชุดย่อยลงไป:

```bash
# ข้อมูลแบบแยกคลังวิชา (slot ใช้ option_codes)
py build_preview.py schedule_view.html data_comiot_demo.json schedule_comiot.html \
    --courses courses_comiot_demo.json
py check_export.py schedule_comiot.html      # ตรวจว่า JSON ที่ฝังใหม่ยัง parse ได้

# หน้า tree + ตัวกรองแผน (ข้อมูลตัวอย่างสมมติที่มี 3 แผน)
py build_preview.py tree_view.html data_tree_demo.json tree_demo.html
py check_export.py tree_demo.html            # ดูตัวเลข "วิชาบังคับตามแผน" ต่อแผน
```

### 7.5 ลดขนาดไฟล์: แยก "คลังวิชา" (course pool) — ไม่ตัดวิชาทิ้ง

**ปัญหา:** รายการวิชาเลือกชุดใหญ่ (ศึกษาทั่วไป ~180 วิชา, ภาษา ~70 วิชา, เฉพาะสาขา ~50 วิชา) ถูกคัดลอกซ้ำ
ลงทุกช่อง ทุกแผน ทุกเทอม ใน ComIoT เพียงหลักสูตรเดียวมี `options` ซ้ำกัน ~700 รายการ ทั้งที่วิชาจริงซ้ำกันเยอะมาก

**วิธีแก้:** เก็บรายการวิชาไว้ที่เดียว แล้วให้แต่ละช่องอ้างด้วยรหัส

```jsonc
// เดิม: ช่องเลือก 1 ช่อง พกวิชา 180 รายการ
{ "group_name": "กลุ่มวิชาเลือกหมวดวิชาศึกษาทั่วไป", "slot_count": 1,
  "options": [ { "code": "90642001", "name_th": "...", "credits": 1 }, ... ] }

// ใหม่: อ้างรหัส
{ "group_name": "กลุ่มวิชาเลือกหมวดวิชาศึกษาทั่วไป", "slot_count": 1,
  "option_codes": ["90642001", "90642011", "90642120"] }

// คลังวิชา courses.json (เก็บครั้งเดียว ไม่ซ้ำ)
{ "app": "course-pool", "version": 1, "count": 11,
  "courses": { "90642001": { "code": "90642001", "name_th": "...", "credits": 1 }, ... } }
```

**สิ่งที่สคริปต์ `split_course_pool.py` ทำให้:**

1. รวม `options` ของ **ทุกช่อง ทุกแผน ทุกหลักสูตร** เป็นคลังเดียว (dedupe ด้วยรหัสวิชา)
2. **ตัดรหัสซ้ำภายในช่องเดียวกัน** และรายงานจำนวนที่พบ (กรณีที่แผนมี option ซ้ำกันจริง)
3. แปลง slot เป็น `option_codes` — **ไม่มีวิชาใดถูกตัดทิ้ง** ทุกช่องยังเลือกได้ครบเท่าเดิม
4. ถ้ารหัสเดียวกันแต่ **ชื่อหรือหน่วยกิตไม่ตรงกัน** จะรายงานเป็น conflict ให้ตรวจ (เก็บค่าแรกไว้)
5. เขียน `courses.json`, `data.json` (แบบเบา), และ `schedule.html`

```bash
# ไฟล์เดียวจบ — ฝังคลังวิชาลง HTML (แนะนำ: เปิดจาก file:// ได้ ไม่ต้องตั้งเซิร์ฟเวอร์)
py split_course_pool.py data_full.json --template schedule_view.html

# แยก courses.json ต่างหาก (ไฟล์ HTML เล็กลงอีก แต่ต้องโหลดคลังวิชาเอง)
py split_course_pool.py data_full.json --template schedule_view.html --split
```

**โหมดแยกไฟล์ (`--split`) โหลดคลังวิชาได้ 3 ทาง** — หน้าเว็บเลือกให้อัตโนมัติตามลำดับ:

| ทาง | เงื่อนไข | หมายเหตุ |
|---|---|---|
| ฝังใน HTML | build แบบไม่ใส่ `--split` | เร็วที่สุด ใช้ได้แม้เปิดจาก `file://` |
| `fetch('courses.json')` | เปิดผ่าน http และมีไฟล์อยู่ข้าง ๆ | ถ้าเปิดจาก `file://` เบราว์เซอร์จะบล็อก (CORS) แล้วตกไปทางถัดไป |
| กดปุ่ม / ลากไฟล์มาวาง | ทุกกรณี | ใช้ `fileInput` ตัวเดียวกับ import — ตัวเว็บแยกเองว่าเป็นไฟล์แผนหรือไฟล์คลังวิชา |

> `schedule_view.html` v3 ยังรองรับข้อมูลแบบดิบ (slot มี `options`) เหมือนเดิม และถ้าเจอ `option_codes`
> ที่ไม่มีในคลัง จะขึ้น "(ไม่พบวิชานี้ในคลังวิชา)" + นับจำนวนที่ขาดไว้ในบรรทัดคำอธิบาย
> ไม่ใช่ปล่อยให้ช่องว่างเงียบ ๆ

### 8.1 วิธีแก้ข้อ 2 (ชื่อหลักสูตรตอนบันทึก)

ในไฟล์ `schedule_view.html` ให้แก้ฟังก์ชัน `getCurriculumName()` โดยอ่านจากหลักสูตร/แผนที่กำลังเลือกอยู่จริง
แทนการอ่าน property ที่ไม่มีใน `DATA`:

```js
function getCurriculumName() {
    const c = DATA[curriculumSelect.value];
    if (!c) return 'แผนการเรียน';
    const plan = (c.plans || []).find(p => String(p.id) === String(planSelect.value));
    return plan && plan.code ? `${c.name} (${plan.code})` : c.name;
}
```

> ผลข้างเคียงที่ตั้งใจไว้: ชื่อไฟล์จะแยกตามแผนด้วย (เช่น `..._(COOP)_2026-10-31-16-07.json`)
> และตอน `import` จะมีการเตือนถ้าเอาไฟล์ของแผน PROJECT ไปโหลดในหน้า COOP ซึ่งเป็นพฤติกรรมที่ต้องการ

### 8.2 วิธีแก้ข้อ 4 (ตัวเลือกแผนที่เรียนไม่จบ)

> **สถานะ: ใส่ไว้ใน `schedule_view.html` v2 แล้ว** — เพิ่มจากตัวอย่างข้างล่างอีก 2 อย่าง คือ
> (ก) เลือกแผนจริงเป็นค่าเริ่มต้นเสมอ (`planSelect.value = realPlans[0].id`) และ
> (ข) แสดงแบนเนอร์สีส้มเตือนใต้ชื่อหลักสูตรเมื่อผู้ใช้เลือกตัวเลือกที่ไม่ใช่แผนจริง แต่หลักสูตรนั้นมีแผนจริง
> พร้อมบอกว่าควรเลือกแผนใด

ให้ตัวเลือก "เฉพาะวิชาที่ใช้ร่วมกันทุกแผน" สื่อความหมายถูกต้อง ในฟังก์ชัน `populatePlanSelect` ของ `schedule_view.html`:

```js
function populatePlanSelect(curriculumIdx) {
    const c = DATA[curriculumIdx];
    planSelect.innerHTML = '';

    const realPlans = c.plans.filter(p => (p.code || '').trim());
    const isPseudo  = p => !(p.code || '').trim();

    c.plans.forEach(p => {
        const opt = document.createElement('option');
        opt.value = p.id;

        if (isPseudo(p)) {
            // มีแผนจริง → เตือนว่าไม่ครบ / ไม่มีแผนจริง → บอกว่าเป็นแผนเดียวของหลักสูตร
            opt.textContent = realPlans.length
                ? '⚠ วิชาที่ใช้ร่วมกันทุกแผน (ยังไม่ครบหลักสูตร)'
                : 'หลักสูตรนี้ไม่มีแผนทางเลือก';
        } else {
            opt.textContent = `${p.code} - ${p.name}`;
        }
        planSelect.appendChild(opt);
    });

    planSelect.selectedIndex = 0;   // เริ่มที่แผนจริงถ้ามี
}
```

ถ้าต้องการซ่อนไปเลยสำหรับหลักสูตรที่มีแผนจริง ใส่ `if (isPseudo(p) && realPlans.length) return;` ในลูป
แต่ **อย่าซ่อนสำหรับ ComIoT** เพราะจะทำให้ dropdown ว่างและไม่มีแผนให้ดูเลย

---

## 9. ถ้าต้องการแก้ไขข้อมูลจากเว็บจริงๆ

แนวทาง static นี้ **แก้ไขข้อมูลในฐานข้อมูลไม่ได้** โดยธรรมชาติ ถ้าอนาคตต้องการ:

- เปิดให้เพิ่ม/แก้/ลบวิชา หมวด หรือแผน จากหน้าเว็บ
- ต้องการให้ข้อมูล real-time ไม่ต้อง export ใหม่

ให้กลับไปพัฒนา `web/` (FastAPI + Jinja2) ที่มีอยู่แล้วในโปรเจกต์ (`uvicorn web.main:app --reload`)
โดยต้องเพิ่ม session-per-request, ระบบ auth และ validation — ซึ่งเป็นงานคนละขอบเขตกับส่วนนี้

## สรุปสั้นๆ

- เปิดไฟล์ `.html` ได้เลย ไม่ต้องติดตั้งอะไร ไม่ต้องต่อเน็ต
- ใช้ดูข้อมูล (tree) และลองจัดแผนการเรียน + คิด GPA เบื้องต้น (schedule)
- ค่าที่กรอกไม่ถูกบันทึกลงฐานข้อมูล — เก็บได้เฉพาะผ่าน "บันทึกเป็นไฟล์" (.json)
- ข้อมูลเป็นสแนปช็อต → รันสคริปต์ export ใหม่เมื่อข้อมูลต้นทางเปลี่ยน
